# Project: David Shadle Website v4

This is an **Effortless Rulebook (ERB)** project. The SSoT is
`effortless-rulebook/effortless-rulebook.json`. It is generated into Postgres
SQL under `postgres/` and loaded into a local Postgres DB (running in Docker)
by `init-db.sh`. The rulebook is edited directly (Rulebook-First — there is no
Airtable/Excel/Notion input spoke on this project).

## What this project is

A personal/professional promotion site for David Shadle, replacing the
existing davidshadle.com. Site content — bio variants, work/proof entries,
resume entries, how-I-work method sections — is modeled as rulebook data
rather than hardcoded page copy, per the "content and navigation are data,
not code" discipline described in `David_Shadle_Content_Strategy_v1.md`.

Source content lives at the project root:
- `David_Shadle_Content_Strategy_v1.md` — positioning, voice, site structure (see Sections 9-11)
- `David_Shadle_Bio_Set_v1.md` — bio variants (one line, 50/150/300 word, LinkedIn About)
- `David_Shadle_How_I_Work_v1.md` — method statement (full page + short version)
- `David_Shadle_Resume_Variants_v1.md` — Variant A (public/consulting) and Variant B (principal, not published)

**Site structure (agreed, Section 10):** Home, How I Work, Work, Resume, Contact
(a section, not a page). No tabs, long scroll over deep navigation. This phase
is setup only — visual design and final page layouts are a later phase.

## CRITICAL RULES — Read Before Doing Anything

1. **`effortless-rulebook.json` is the Single Source of Truth.** It is the hub.
   There are no input spokes on this project (no Airtable/Excel). Postgres and
   any generated app code are *output spokes* regenerated by `effortless build`.
2. **NEVER edit generated files** in `postgres/` — they are regenerated on every build.
3. **Always read from `vw_*` views**, never base tables. Always WRITE to base tables directly.
4. **Query the rulebook FIRST — NEVER read it directly.** Use targeted python
   one-liners (see `effortless-query`) instead of a full `Read`/`cat` of the file.
5. **Ask permission** before modifying the rulebook or running `effortless build`.
6. **Always run `effortless build`** after any change reaches the rulebook hub.
7. **Never reimplement business logic** in app code — consume calculated fields
   from views as opaque truth.
8. **NO MIGRATIONS.** `init-db.sh` drops + recreates the local Postgres DB on
   every build. There is no `migrations/` folder. If the answer feels like
   "write a migration," the answer is "edit the rulebook and rerun `effortless build`."

## Local Postgres (Docker)

Postgres runs via `docker-compose.yml` at the project root, exposed on
`localhost:5432`. There is no native Postgres/psql install on this machine —
use `docker exec -it <container> psql -U postgres -d <dbname>` to query, or
`docker compose up -d` / `down` to manage the container.

## Editing the Hub

Edit `effortless-rulebook/effortless-rulebook.json` directly (with permission),
then `effortless build`.

## The Effortless Loop

CHANGE RULE (in rulebook JSON) → `effortless build` → CONSUME generated views
in app code → repeat. On "do a turn" / "rebuild", load `effortless-loop`.

## Build & Start

- Build: `effortless build` from project root
- Start: `./start.sh` from project root
- Postgres: `docker compose up -d` (starts container), `./start.sh db` (re-runs init-db.sh)

## NO MIGRATIONS — read before touching Postgres

This project's local Postgres DB is regenerated from scratch on every
`effortless build` via `init-db.sh` (drop + recreate). There is no
`migrations/` folder, no migrations tracking table, no incremental SQL deltas.

**To change schema, calculated fields, or seed data:**
1. Edit the rulebook.
2. Run `effortless build`.
3. The DB is wiped and rebuilt. Done.

**Never on this DB:** `CREATE TABLE` / `ALTER TABLE` / `DROP TABLE` by hand,
files under `postgres/migrations/`, a `migrations` tracking table, or hand
edits to generated `0*.sql` files.

## Build discipline (applies every time)

`effortless build` regenerates `effortless-rulebook/` and `postgres/` and
drops + re-inits the local Postgres DB. Effortless skills are read-only with
respect to git (`git status`, `git diff`, `git log` only — never `git add`/
`git commit`). Before building on a dirty tree, ask for permission first.
After building, leave the tree for the user to commit.
